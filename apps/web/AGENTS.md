# Web Workspace Instructions

Scope: applies when working in the Vite web app, Joy UI components, PWA shell, or client data loading (`apps/web/**`).

UI conventions (look, theming, dialogs, empty states, icons, PWA install) are in `.agents/guides/ui-conventions.md`; read it before changing any UI.

- Server data goes through TanStack Query: the client is `src/lib/queryClient.ts`, every key comes from `src/lib/queryKeys.ts`, and requests go through `apiRequest` in `src/lib/apiQuery.ts`. UI-only state stays in local React state. Add no other state library.
- Use shared schemas to validate server responses where practical so the frontend fails loudly when contracts drift.
- Prefer browser-first flows and platform standards over custom client-specific behavior.
- Brand icons in `apps/web/public` are generated by devkit-icons (`npm run icons`) from the masters in `assets/brand/`; edit a master and regenerate rather than hand-editing the emitted SVGs or PNGs, and keep text in the masters as path outlines so any rasterizer produces identical output. The tab favicon (`icon-up-bang-64.png`) is an app-owned extra outside the generator (see `assets/brand/README.md`).
- When changing the Game's Up PWA icon assets or icon references, keep `apps/web/vite.config.ts` and `apps/web/index.html` aligned and bump the shared icon version query string so installed clients are forced to fetch the updated icon URLs.
- Keep the admin DM preview surfaces aligned with live Discord output. If the API adds or changes DM copy, embeds, buttons, or preview fields, update the web debug surfaces in the same change so the read-only previews continue to render supported message states correctly.

## Shared Helpers

- Build API URLs through `buildApiUrl` and `buildAbsoluteApiUrl` in `apps/web/src/lib/apiUrl.ts`. Do not concatenate base URLs inline.
- Read browser env (Vite `import.meta.env`) through `apps/web/src/lib/browserEnv.ts` so server-render contexts and tests can stub it.
- Extract API error messages with `extractErrorMessage` from `@game-is-up/shared` instead of repeating ad-hoc shape checks.
- Reset local state that follows a prop (a dialog on open, a draft from saved data) with `useResetOnChange` from `@dynamic-solutions-canada/web-app-kit`, which resets during render, never with an effect that calls a setter. Start the state at the value a reset produces.
- When a stored choice can become invalid (a removed server, an out-of-range index), keep the user's choice and derive the effective value during render instead of overwriting it.
- Read the time for rendering from `useNow()` in `src/hooks/useNow.ts` (one shared 30-second clock), never `Date.now()` in render; a check made at a moment, such as on save, reads `Date.now()` in its handler. The React Compiler lint rules (`refs`, `set-state-in-effect`, `purity`) are errors; a genuine sync with something outside React keeps its effect with a one-line waiver that gives the reason.
- Dashboard data flow is composed in `useDashboardApp.tsx` from the play / library / invites sub-hooks; new dashboard surfaces should attach there rather than instantiating their own duplicate fetchers.
